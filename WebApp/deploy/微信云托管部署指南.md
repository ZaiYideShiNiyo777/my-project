# 全行业可信信息聚合平台 — 微信云托管 + 腾讯云静态托管部署指南

> 适用：把本仓库 `webapp` 分支部署为公网可访问的实时信息聚合网站（手机/平板/电脑均可访问）。
> 架构：**微信云托管**（FastAPI 后端容器 + 抓取调度器 + MySQL + Redis）＋ **腾讯云静态网站托管**（前端 dist，可绑定已备案域名）。

---

## 1. 架构总览

```
手机/平板/电脑浏览器
        │  https://你的域名（静态托管）
        ▼
腾讯云静态网站托管（index.html + assets）
        │  前端 JS 直连后端公网域名（VITE_API_BASE，CORS 已放开）
        ▼
微信云托管容器（uvicorn :8000）
        ├── 启动时：python -m app.seed（建表 + 幂等灌入 107 条种子数据）
        ├── 常驻：scraper daemon（每 300s 一轮：Git inbox + HTTP 源）
        └── 依赖：内置 MySQL（业务库）+ 内置 Redis（热点缓存，可降级）
```

- 前端 `dist-web.zip`：约 80 KB（Vue3 + Vite 构建产物，纯静态）
- 后端 `backend-deploy.zip`：Dockerfile + app + scraper + data（含 Dockerfile，构建目录选 `/`）

## 3. 第一步：部署后端（微信云托管）

### 3.1 准备代码包

仓库已含全部部署文件。打包含命令（或在仓库根执行部署脚本时自动生成）：

```powershell
cd D:\AI\WebApp
tar -a -c -f backend-deploy.zip -C backend --exclude=.venv --exclude=__pycache__ --exclude=*.pyc --exclude=dev.db --exclude=test_scraper*.db --exclude=scraper.log --exclude=data/inbox/done .
```

> 校验：zip 根目录必须能看到 `Dockerfile`、`requirements.txt`、`app/`、`scraper/`、`data/`。

### 3.2 创建服务并部署

1. 打开微信云托管控制台 → 选择/创建环境（计费方式任选，有免费额度）。
2. **创建服务**：服务名 `trust-api`，部署方式选 **"代码包/本地代码"**（也可选 GitHub 仓库绑定自动构建，Dockerfile 路径填 `backend/`）。
3. 上传 `backend-deploy.zip`；**构建配置**：构建目录 `/`（zip 根目录即 Dockerfile 所在目录）、语言 Python、端口 **8000**。
4. 点击 **部署**（首次构建拉取 python:3.12-slim + 腾讯云 PyPI 镜像装依赖，约 2~5 分钟）。
5. 部署成功后，在服务详情页记录 **公网访问域名**（形如 `https://trust-api-xxxxx.ap-shanghai.run.tcloudbase.com`，自带 HTTPS 证书）→ 记为 `API_DOMAIN`。

### 3.3 创建 MySQL 与 Redis（云托管内置）

1. 控制台 **数据库** 菜单 → 创建 MySQL（8.0）：实例名 `trust-db`，**数据库名填 `trust_aggregator`**；记下内网地址、端口（3306）、账号、密码。
2. 控制台 **缓存** 菜单 → 创建 Redis：实例名 `trust-cache`；记下内网地址、端口（6379）、密码（如有）。
3. 若控制台未自动建库，用任意 MySQL 客户端执行：`CREATE DATABASE IF NOT EXISTS trust_aggregator DEFAULT CHARSET utf8mb4;`

### 3.4 配置环境变量

回到服务 `trust-api` → **服务设置 → 环境变量**，添加：

| 变量 | 值（示例） | 说明 |
|---|---|---|
| `DATABASE_URL` | `mysql+pymysql://root:你的密码@内网IP:3306/trust_aggregator?charset=utf8mb4` | 业务库（必须） |
| `REDIS_URL` | `redis://:你的密码@内网IP:6379/0` | 热点缓存（可选，缺失自动降级不缓存） |
| `SCRAPER_INTERVAL` | `300` | 抓取轮询间隔（秒），默认 300 |
| `SCRAPER_SAMPLE_FEED` | `https://www.gov.cn/.../feed.xml`（可选） | HTTP 采集源 RSS/JSON；留空则仅 Git inbox 投递 |

保存后点击 **重新部署**（环境变量变更需重建容器）。

### 3.5 验证后端

浏览器打开 `API_DOMAIN/api/health`，应返回：

```json
{"code":0,"message":"ok","data":{"status":"up"}}
```

再验证 `API_DOMAIN/api/feed?page_size=2`：`data.total` 应为 107（种子数据已入库）。

## 4. 第二步：部署前端（静态网站托管）

### 4.1 构建

在仓库 `frontend/` 目录执行（`ApiBase` 填 3.2 步记录的后端域名）：

```powershell
cd D:\AI\WebApp\frontend
powershell -NoProfile -ExecutionPolicy Bypass -File .\build-prod.ps1 -ApiBase "https://trust-api-xxxxx.ap-shanghai.run.tcloudbase.com"
```

- 脚本自动写 `.env.production`（UTF-8 无 BOM）→ `vite build` → 生成 `dist-web.zip`（仓库根目录）。
- 产物中 `baseURL` 已被替换为后端域名（可解压 zip 后 grep 验证）。

### 4.2 上传

1. 微信开发者工具 → 云开发控制台 → **静态网站托管**（或腾讯云 CloudBase 控制台）。
2. 上传解压后的 `dist` 目录内容（`index.html` + `assets/`），或直接传 `dist-web.zip` 由控制台解压。
3. 得到默认访问域名 `https://xxxx.tcloudbaseapp.com` → 打开验证首页信息流。

### 4.3 绑定自定义域名（已备案）

1. 静态托管控制台 → **域名管理** → 添加域名（如 `news.你的域名.com`）。
2. 按提示到域名服务商加 **CNAME** 记录指向静态托管分配的 CNAME 地址。
3. 等待解析生效（几分钟），HTTPS 证书由平台自动签发。

> 未备案域名只能使用平台默认 `tcloudbaseapp.com` 域名访问。

## 6. 发布 / 更新流程

### 后端更新（代码变更）

1. 本地改代码 → 提交推送 GitHub `webapp` 分支。
2. 重新执行 3.1 打包命令 → 云托管控制台 **发布新版本**（上传新 zip）。
3. 容器启动自动：`seed`（幂等，不重复灌数据）→ 拉起 daemon → 提供 API。

### 前端更新

1. 改前端代码 → 重跑 `build-prod.ps1`（ApiBase 不变）。
2. 静态托管控制台覆盖上传新 `dist`（或上传新 zip 切换版本）。

### 投递新消息（实时抓取核心用法）

- **方式一（推荐）**：把消息 JSON（格式见 `backend/data/inbox/examples/sample.json`）放入 `backend/data/inbox/` → 提交推送 GitHub → 后端重新部署。daemon 启动后自动消费入库（白名单校验 → 可信度过滤 → 去重）。
- **方式二**：配置 `SCRAPER_SAMPLE_FEED` 指向真实 RSS/JSON 源，daemon 每 300s 自动拉取（需源域名命中 `trusted_sources` 白名单，可在 seed 的 SOURCES 或数据库中添加）。

## 7. 实时抓取运行状态查看

1. 微信云托管控制台 → 服务 `trust-api` → **日志**（stdout）。
2. 每轮抓取会输出：
   - `scraper.run: === 开始一轮抓取 ===`
   - `scraper.run: Git inbox: 扫描 x / 新增 y ...`（入库统计）
   - `scraper.run: === 本轮抓取结束 ===`
3. 数据量检查：浏览器访问 `API_DOMAIN/api/feed?page_size=1`，`data.total` 应随时间增长。

## 8. 维护注意事项

- **数据库持久化**：数据在云托管内置 MySQL 中，与容器生命周期无关，放心重启/更新。
- **容器重启不影响幂等**：seed 有数据即跳过；inbox 已处理文件在容器内不持久，重启后会重新消费但入库去重（source_url 唯一），不会产生重复。
- **费用**：云托管按容器规格 + 流量计费，静态托管有免费额度；MySQL/Redis 为独立实例按量计费（可开最低配）。不用时可在控制台**缩容到 0/停用**省钱。
- **安全**：容器端口 8000 仅云托管内网/公网域名暴露；数据库不开放外网。建议定期更新数据库密码并同步改环境变量。
- **备份**：MySQL 控制台开启自动备份；前端 zip 可随时从仓库重新构建。

## 9. 常见问题

| 问题 | 处理 |
|---|---|
| 首页加载但列表为空/离线提示 | 检查 `VITE_API_BASE` 是否注入（重跑 build-prod.ps1）；浏览器 F12 看请求地址 |
| 接口 502/超时 | 云托管容器未就绪或缩容到 0；控制台查看部署状态与日志 |
| seed 报错 | 确认 `DATABASE_URL` 指向的库存在且字符集 utf8mb4 |
| 抓取日志无输出 | 确认部署的是最新 Dockerfile（CMD 含 `--daemon`）；日志面板选择 stdout |
| 域名打不开 | CNAME 未生效或未绑定；HTTPS 证书签发需几分钟 |
